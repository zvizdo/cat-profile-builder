## How every task is executed (read first)

1. **Implement.** `[TDD]` tasks: write the named tests, run them, **see them fail**, write the minimum
   code, see them pass, refactor. Everything else: build, then test.
2. **Gates.** Run `pnpm lint && pnpm format:check && pnpm typecheck && pnpm test` (add
   `pnpm gen-tokens --check` when tokens changed; `pnpm build && pnpm test:e2e` for tasks that name an e2e
   test). Paste what you saw. "Green" means you saw it.
3. **Live check.** Every task that changes something a person sees ends with a **Browser check**: start
   `STORE=fs MODEL=fake pnpm dev`, open `http://localhost:3000/fundraiser?...`, and drive the feature in a
   real browser (Playwright MCP tools or a script under `tests/e2e/`) on a **desktop size and a phone
   size**. Click, type, read the console, take a screenshot of the end state. Report what you saw, never
   "should work".
4. **Reviewer.** `[REVIEW]` tasks stop for a human after the live check; do not start dependants until
   cleared. Checklist boxes under `checklists/` are the reviewer's: never tick, untick, or reword them.
5. **Commit.** One commit per task, message `<type>(<scope>): <task id> <title>`, **no AI or Claude
   trailers**. Commit only when the user asks (CLAUDE.md), unless they grant standing permission for this
   feature. Nothing is pushed without asking.

**`[UI]` tasks — design discipline.** Work inside the design system: `references/design/DESIGN.md`,
`TOKENS.json` (the only nameable values; `src/ui/tokens.css` is generated by `pnpm gen-tokens` and never
edited by hand), `CONTENT.md` (voice: plain, specific, sentence case, no emoji, says what happened and what
to do). The brainstorm mockups are in `.superpowers/brainstorm/89329-1791326878/content/` (git-ignored,
local only) and are the visual reference for the numbers in `contracts/display-layout.md`.

### Global constraints (apply to every task)

- TypeScript `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`; no `any`; **no `as` on untrusted
  data**: the query string and field text are `unknown` until a Zod schema or a validator passes them
  (Principle IV).
- `src/core/fundraiser/` never imports `react`, `next/*`, or any `server-only` module (ESLint
  `no-restricted-imports` already covers `src/core/**`). It may import `zod` and `@/core/result`.
- Every exported function, type, and component carries a doc comment saying what it is for and what it
  guarantees (Engineering Standards); comments explain why, not what.
- Coverage: core ≥ 95 % lines and branches, app ≥ 80 %, over unit + component + contract only. **No new
  line in the exclusion list in `vitest.config.ts`.**
- No new dependency. No `console.log`. No `dangerouslySetInnerHTML`. No `localStorage`, `sessionStorage`,
  cookie, or server write anywhere in this feature (FR-022).
- Motion: only `transform` and `opacity` animate. Nothing animates on load. No decorative motion.
- Text on the display is never smaller than `max(10px, 2.4cqmin)`. Touch targets ≥ 44 px. Every
  interactive element is operable by keyboard with visible focus, and has a component test of its keyboard
  path and accessible name.
- Components stay under 200 lines, functions under 50, complexity under 10 (lint warnings; split rather than
  justify).
- Every string a person reads lives in `src/ui/fundraiser/strings.ts`; core returns reason **codes**.

### Review Focus (inputs the spec implies but no acceptance scenario names)

Each line has its test in the task named at the end.

1. **One cent either side of a milestone** ($2,499.99 and $2,500.00 of $10,000): the 25 % paw lights only at
   the second, and the tag never shows 25 % over a dark paw — T005.
2. **Pasted text with a newline, tab, or non-breaking space** in an amount or headline field: amounts are
   refused with a plain message, the headline's whitespace collapses — T002, T003.
3. **A hostile or enormous address**: 10 000-character headline, doubly encoded `%2520`, repeated keys,
   zero-width-only headline — T004, T018.
4. **Rotating a device or resizing the window while a field is open**: the open field, its text, and the
   arrangement survive — T017, T020.
5. **Escape or the browser's exit from full screen while a draft existed**: the page comes back clean, with
   the same numbers and no stale session — T013, T016.

## Implementation strategy

**MVP first.** Phases 1–3 deliver a display that renders from an address and goes full screen: already
useful for a shelter that sets its numbers by editing the address by hand. Add US2 (editing) next, then
US3's write (a screen survives a reload after an edit), then US4 (headline). Stop at any checkpoint to
validate that story on its own. Each of T002–T007 and T015–T016 can go to a fresh subagent with its task
text and the files it names; T012, T017, T019 are the visually judged tasks and stay with a person at the
checkpoint.
